# ML confirmation: present + future forecast

Ниже описание текущего поведения и целевого поведения.  
Нужно подтверждение от ML-инженера: **верно / неверно**, и что нужно поправить.

## 1) Как работает сейчас (наше понимание)

1. На вход ML приходит `timeseries[]` по тайлу (исторический ряд признаков).
2. ML возвращает **один** результат на тайл и модуль (`m0/m1/m2`), без поля `date`.
3. Backend агрегирует эти результаты в средние по полю.
4. Эти средние повторяются для всех дат workflow-прогона.

Следствие: график прогноза по времени выглядит как почти горизонтальная линия (константа).

## 2) Проблема

Нужен прогноз, который описывает:

- **настоящее** (оценка «сейчас»),
- **будущее** (изменение по датам/горизонтам).

Текущий output без даты даёт только «сводный скор по истории», но не временной прогноз.

## 3) Целевое поведение

ML output должен быть time-aware:

- `now` (оценка текущего состояния),
- `forecast[]` (прогноз на будущие даты или горизонты).

Пример формата (черновой):

```json
{
  "module": "m1",
  "field_id": "uuid",
  "tile_id": "uuid",
  "now": {
    "date": "2026-03-20",
    "health_score": 67,
    "stress_score_total": 42
  },
  "forecast": [
    { "date": "2026-03-27", "health_score": 64, "stress_score_total": 45 },
    { "date": "2026-04-03", "health_score": 61, "stress_score_total": 49 },
    { "date": "2026-04-10", "health_score": 58, "stress_score_total": 53 }
  ]
}
```

## 4) Что это меняет в интеграции

Backend:

1. Агрегировать прогнозные метрики по полю **по каждой forecast-дате**.
2. Сохранять их в `field_analytics_timeseries` как `source='predicted'` с `observation_date = forecast_date`.

Frontend:

1. Рисовать оранжевую линию по реальным forecast-датам.
2. Плоская линия исчезнет, если прогноз действительно меняется во времени.

## 5) Вопросы к ML (подтвердить)

Пожалуйста, подтвердите по пунктам:

1. Верно ли, что сейчас модель возвращает один итоговый скор на тайл без `date`?
2. Может ли модель вернуть `now + forecast[]` (date-aware output)?
3. Какие горизонты прогнозов корректны с вашей стороны: `+7/+14/+30`, weekly, daily, другие?
4. Какие поля прогнозируем гарантированно по каждому модулю (`m0/m1/m2`)?
5. Нужны ли доверительные интервалы (`p10/p50/p90` или `lower/upper`) в output?
6. Есть ли ограничения по минимальной длине входного `timeseries[]`?

## 6) Что считаем подтверждением

Подтверждение = ответ ML-инженера:

- «Да, текущее описание верно» или исправления к нему,
- согласованный формат output (с датами),
- согласованные горизонты и обязательные поля.
